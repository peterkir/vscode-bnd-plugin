# Changelog

## 0.25.0

### Added
- User documentation with screenshots: README feature sections, a step-by-step **Workspace Wizards** guide from an empty folder to an Eclipse RCP application, a new *Create a Workspace* walkthrough step, and images in the existing walkthrough pages. `scripts/screenshots.mjs` regenerates the images from an Extension Development Host (see DEV.md).
- `examples/com.example.rcp`: the Eclipse RCP workspace generated by the wizards (E4 application and SWTBot tests), excluded from the VSIX. `scripts/exampleWorkspace.mjs` (`npm run example -- generate|import|prepare|test`) regenerates it headlessly through the bundled language server, copies it to a scratch folder for the Extension Development Host, and runs its SWTBot tests with the bnd CLI.

### Fixed
- In `java` server mode, output that bnd workspace plugins or extensions print to `System.out` no longer breaks the language-server connection ("Header must provide a Content-Length property"). Stray output is logged to the **bnd Language Server** output channel and the protocol stream is re-synchronized.
- The Effective properties view no longer re-evaluates continuously when a Git repository is open. Dependency watchers now react only to real file changes of the dependency files, not to Git quick-diff (`git:`) resource events.

## 0.24.0

### Added
- Property-conflict diagnostics with quick fixes in `java` server mode: duplicate definitions and `-include` shadowing of merged-property keys are reported from the unsaved editor text following the bnd `-propertyconflicts` policy. Quick fixes rename a merge-capable key to a unique `key.<suffix>` or remove the conflicting definition.
- Quick fixes to remove an invalid `Bundle-Activator` header and to change `Bundle-Version` to the version suggested by baselining, keeping a macro qualifier.

### Changed
- Update the bundled `biz.aQute.bnd.lsp.jar` to the language server rebased on current bnd master (includes `-propertyconflicts`, `resolution:=conditional`, JUnit 6 tester, and P2 repository cache support from upstream).

## 0.23.5

## 0.23.4

## 0.23.3

## 0.22.2

## 0.22.1

Workspace templates support GitHub repository and ZIP locations; fragment catalogs stay separate and legacy fragment settings no longer affect workspace creation.

## 0.22.0

## 0.21.0

### Added
- **bnd: Create Workspace...** selects composable workspace fragments from upstream or custom catalogs, confirms source trust, previews generated files, and creates a new/empty workspace through the Java server. Existing-workspace updates and project templates remain unsupported.
- **bnd: Import Workspace...** validates an existing bnd root and opens it in the current/new window or adds it to a multi-root workspace. Import preserves existing files and does not build or evaluate bnd configuration.

## 0.17.0

### Added
- **bnd JAR Viewer**, a port of the bndtools Eclipse JAR editor and the default editor for `.jar` files. The **Tree** page lists the archive entries, selects `feature.xml` or `META-INF/MANIFEST.MF` initially, and shows the selected entry as text or hex (Auto/Text/Binary (hex)), with a text encoding choice, size, last modified time and the 1,000,000-byte read limit. Double-click an entry to open it read-only in an editor (`bnd-jar:` scheme). The **Print** page shows the full `bnd print` report from the Java language server.
- **Open with bnd JAR Viewer** in the Explorer and bnd Explorer context menus for `.jar` files.

### Changed
- Bundled Java language server adds `bnd.jar.printText`, which returns the bndtools JAR editor print report (all `JarPrinter` options).

## 0.15.0

### Added
- **bnd** Activity Bar container with a **Repositories** view, a port of the bndtools Eclipse Repositories view. It shows one root per bnd workspace (`cnf/build.bnd`), with the Workspace repository (projects and their bundles), plugin repositories, bundles, versions, and P2 features with their included and required items.
- View actions: filter by bundle symbolic name, advanced requirement search (package, service, or any namespace and LDAP filter), refresh, collapse all, and toggle offline mode.
- Item actions: add JARs to writable repositories (also by dropping files on a repository), download remote content, copy the bundle symbolic name, version, or bnd entry, reveal the JAR, show the manifest, and run repository-specific `Actionable` actions.
- Drag bundles or versions into a bnd editor to insert `bsn;version=...` entries.
- Walkthrough step **Browse Repositories**.

### Changed
- Bundled Java language server adds `bnd.repositories.*` commands and `bnd.workspace.offline`. All of them require workspace trust.
